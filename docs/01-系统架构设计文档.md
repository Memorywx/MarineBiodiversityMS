## 2. 系统分层架构（后端）

```
┌─────────────────────────────────────────┐
│  Controller 层   (@RestController)      │  ← 接收请求，参数校验，返回DTO
│  职责：URL路由、入参校验、调用Service      │
├─────────────────────────────────────────┤
│  Service 层      (@Service)             │  ← 业务逻辑编排，事务管理
│  职责：业务流程、权限检查、数据转换        │
├─────────────────────────────────────────┤
│  Mapper 层       (MyBatis-Plus)         │  ← 数据访问
│  职责：SQL映射、复杂查询、分页             │
├─────────────────────────────────────────┤
│  Entity / DTO / VO                      │  ← 数据模型定义
│  职责：数据库实体、传输对象、视图对象        │
└─────────────────────────────────────────┘
```

### 2.1 分层说明
- **Controller**：只负责接收 HTTP 请求、基本参数校验、调用 Service、封装统一响应结果 `Result<T>`。
- **Service**：处理业务逻辑，一个 Service 对应一个业务模块（如 `SpeciesService`、`ObservationService`）。跨表操作在 Service 层完成，需要时加 `@Transactional`。
- **Mapper**：继承 `BaseMapper<T>`，复杂查询使用自定义 XML 或注解 SQL。
- **Entity**：与数据库表一一对应，只用于持久层。
- **DTO**：数据传输对象，用于 Controller 层接收请求参数（如 `SpeciesCreateDTO`）。
- **VO**：视图对象，用于返回给前端的数据结构（如 `SpeciesDetailVO`）。

## 4. 统一响应格式

### 4.1 通用响应结构 `Result<T>`
```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

### 4.2 分页响应结构 `PageResult<T>`
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [ ... ],
    "total": 100,
    "size": 10,
    "current": 1,
    "pages": 10
  }
}
```

### 4.3 状态码定义
| code | 含义 |
|------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或Token过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 5. 认证与授权设计

### 5.1 JWT Token 方案
- 用户登录成功后，后端生成 JWT（含 userId、username、role、过期时间）。
- 前端将 Token 存入 `localStorage`，每次请求通过 `Authorization: Bearer <token>` 携带。
- 后端 `JwtAuthenticationFilter` 拦截请求，解析 Token 并设置 SecurityContext。

### 5.2 RBAC 权限模型
- **角色枚举**：`ADMIN`(管理员)、`RESEARCHER`(科研人员/教师)、`STUDENT`(学生)、`PUBLIC`(公众)。
- 每个 API 通过 `@PreAuthorize("hasRole('RESEARCHER')")` 或自定义注解控制访问。
- 数据级权限（如公众只能看公开数据）在 Service 层通过角色判断动态拼接查询条件。

## 7. 核心业务流程

### 7.1 物种信息创建流程
```
前端填写表单 → 上传图片 → 调用 POST /api/species
→ Controller 校验 DTO → Service 保存物种主表
→ 保存图片关联表 → 返回创建成功
```

### 7.2 观测记录创建流程
```
前端填写观测表单（含地图选点）→ 选择关联物种
→ 调用 POST /api/observations
→ Service 保存观测记录主表 → 批量保存观测-物种关联表
→ 返回创建成功
```

### 7.3 数据看板加载流程
```
前端进入首页 → 并行调用多个统计接口
→ GET /api/dashboard/stats（关键指标）
→ GET /api/dashboard/species-stats（物种统计）
→ GET /api/dashboard/observation-stats（观测统计）
→ 前端 ECharts 渲染图表
```
