# 海洋生物多样性信息管理系统

## 软件需求规格说明书（SRS）

**文档编号：** GDOU-SWENG-MARINEBIODIV-SRS-1.0  
**版本：** 1.0  
**日期：** 2026年4月21日

---

## 1. 引言

### 1.1 目的
本文档为“海洋生物多样性信息管理系统”的详细软件需求规格说明书，定义系统必须实现的功能性需求和非功能性需求。本文档面向项目开发团队、测试团队及指导教师，作为系统设计、开发、测试和验收的依据。

### 1.2 项目背景
广东海洋大学以海洋和水产学科为特色，拥有大量涉及海洋生物多样性研究的科研项目和教学任务。目前物种数据分散在各个课题组、教师和个人手中，存在数据格式不统一、管理效率低下、展示形式单一、知识传递壁垒等问题。本系统旨在建立一个集中、规范、易用的Web平台，用于管理、展示和研究海洋生物物种数据。

### 1.3 业务范围
本系统是基于Web的信息管理系统，用户可通过互联网访问。核心业务范围包括：
- 物种信息的增删改查、分类与检索
- 用户注册、登录、角色与权限管理
- 生态系统与观测记录的创建、关联与维护
- 数据可视化展示（地图、统计图表、综合看板）与报表导出

### 1.4 目标用户
| 用户角色 | 描述 |
|---------|------|
| 系统管理员 | 负责用户管理、系统维护和数据备份 |
| 科研人员/教师 | 核心用户，负责录入、维护和分析其研究领域的物种数据 |
| 学生 | 可查询学习相关物种信息，参与课程实践 |
| 公众 | 可访问公开的物种信息，进行学习和科普 |

## 2. 总体描述

### 2.1 系统架构
系统采用 **B/S 架构**，技术选型建议如下：
- **后端框架：** SpringBoot
- **前端框架：** Vue.js（推荐 Vue 3）
- **数据库：** MySQL 或 PostgreSQL
- **地图服务：** 开源地图库 Leaflet（避免依赖商业 API）

### 2.2 模块划分与交互关系

| 模块 | 主要职责 | 核心交互 |
|------|---------|---------|
| 模块一：用户与权限管理 | 系统入口、安全控制 | 为所有其他模块提供身份认证和权限校验服务 |
| 模块二：物种信息管理 | 系统核心数据实体 | 为模块四提供物种数据和分布信息；为模块三提供可关联的物种对象 |
| 模块三：生态系统与观测记录管理 | 新增核心数据实体与业务 | 依赖模块二关联物种；为模块四提供观测记录、地点、生态系统数据 |
| 模块四：数据可视化与报表 | 数据呈现与输出 | 依赖模块二和模块三获取可视化展示和统计分析的数据源 |

**开发优先级：** 模块二 ≈ 模块三 > 模块一 > 模块四

## 3. 功能性需求

### 3.1 模块一：用户与权限管理模块

#### 3.1.1 用户注册
- **需求编号：** SRS-USER-001
- **需求描述：** 学生和公众用户可通过注册页面提交申请。注册信息至少包括用户名、密码、邮箱、角色类型（学生/公众）。
- **业务规则：** 新注册用户需经管理员审核通过后方可激活账号。科研人员/教师账号建议由管理员直接创建或分配。

#### 3.1.2 用户登录与登出
- **需求编号：** SRS-USER-002
- **需求描述：** 已激活用户可使用用户名/邮箱和密码登录系统；登录成功后获得身份令牌（Token）；用户可主动登出，登出后令牌失效。

#### 3.1.3 用户信息维护
- **需求编号：** SRS-USER-003
- **需求描述：** 用户可修改个人基本信息（如昵称、联系方式）和上传/修改个人头像。

#### 3.1.4 用户角色管理
- **需求编号：** SRS-USER-004
- **需求描述：** 系统预定义四种角色：系统管理员、科研人员/教师、学生、公众。管理员可在后台查看用户列表、分配或修改用户角色、禁用/启用账号。

#### 3.1.5 权限控制
- **需求编号：** SRS-USER-005
- **需求描述：** 系统基于角色（RBAC）控制用户对各功能模块的访问和操作权限。
  - 管理员：拥有全部权限
  - 科研人员/教师：可创建、编辑、删除物种信息和观测记录
  - 学生：可查看物种和观测记录，部分字段可能受限
  - 公众：仅可查看公开物种信息，不可操作观测数据

#### 3.1.6 用户活动日志记录
- **需求编号：** SRS-USER-006
- **需求描述：** 系统记录关键用户活动日志，包括登录/登出时间、IP地址、重要数据操作（增删改）等，便于审计和安全追溯。

---

### 3.2 模块二：物种信息管理模块（核心）

#### 3.2.1 物种信息创建
- **需求编号：** SRS-SPECIES-001
- **需求描述：** 授权用户（科研人员/教师/管理员）可通过表单创建物种信息。表单字段至少包括：
  - 基础信息：中文名、学名
  - 分类信息：门、纲、目、科、属、种
  - 描述信息：形态特征、生活习性
  - 分布信息：分布区域（支持经纬度坐标或地理范围描述）
  - 保护信息：保护等级、濒危状态（IUCN等级等）
  - 多媒体：物种图片上传、视频链接
  - 文献：参考文献
- **业务规则：** 中文名和学名为必填项；学名建议保持唯一性校验。

#### 3.2.2 物种信息编辑与更新
- **需求编号：** SRS-SPECIES-002
- **需求描述：** 授权用户可对已存在的物种信息进行编辑和更新。更新后需记录修改时间和修改人。

#### 3.2.3 物种信息删除
- **需求编号：** SRS-SPECIES-003
- **需求描述：** 授权用户可删除物种信息。
- **业务规则：** 删除操作需记录操作日志；若该物种已被观测记录关联，建议提示用户或提供强制删除/转移选项（根据实际业务决策）。

#### 3.2.4 物种信息查询与检索
- **需求编号：** SRS-SPECIES-004
- **需求描述：** 系统支持多条件组合筛选和全文检索，包括但不限于：
  - 按名称检索（中文名、学名模糊匹配）
  - 按分类检索（门纲目科属种层级筛选）
  - 按保护等级、濒危状态筛选
  - 按分布区域筛选
- **展示要求：** 支持分页展示，列表页显示关键摘要信息（名称、分类、保护等级、缩略图）。

#### 3.2.5 物种详情页面展示
- **需求编号：** SRS-SPECIES-005
- **需求描述：** 提供独立的物种详情页，完整展示该物种的所有字段信息、图片画廊、关联的观测记录入口等。

---

### 3.3 模块三：生态系统与观测记录管理模块

#### 3.3.1 生态系统管理
- **需求编号：** SRS-OBS-001
- **需求描述：** 系统支持对海洋生态系统的基础数据进行维护，包括：
  - 创建、编辑、删除、查询不同的海洋生态系统（如珊瑚礁、红树林、海草床、深海、河口等）
  - 每个生态系统包含名称、类型描述、地理范围、环境特征等字段

#### 3.3.2 观测记录创建
- **需求编号：** SRS-OBS-002
- **需求描述：** 授权用户可创建野外或实验室观测记录，字段包括：
  - 基础信息：观测时间、观测地点（支持地图选点，记录经纬度）
  - 关联信息：所属生态系统
  - 人员信息：观测人员
  - 环境参数：水温、盐度、pH值、深度等（可根据生态系统类型动态调整）
  - 备注：文本描述

#### 3.3.3 观测-物种关联
- **需求编号：** SRS-OBS-003
- **需求描述：** 在创建或编辑观测记录时，用户可以关联一个或多个在该次观测中发现的物种。
- **扩展字段：** 对每个关联的物种，需记录：
  - 估算数量
  - 行为描述（如觅食、繁殖、迁徙）
  - 备注
- **业务规则：** 只能从模块二已存在的物种库中选择进行关联；关联关系支持后续编辑。

#### 3.3.4 观测记录查询与维护
- **需求编号：** SRS-OBS-004
- **需求描述：** 系统支持对所有观测记录进行查询、查看详情、修改和删除。
- **查询维度：** 支持按时间范围、地点（地图范围圈选）、生态系统类型、观测人员、关联物种等条件组合筛选。

---

### 3.4 模块四：数据可视化与报表模块

#### 3.4.1 物种分布地图
- **需求编号：** SRS-VIS-001
- **需求描述：** 在集成地图（Leaflet）上展示物种的分布点，数据来源为模块二中记录的分布区域/经纬度。
- **交互要求：** 支持按物种名称筛选后在地图上高亮显示其分布点；点击分布点可查看物种摘要信息。

#### 3.4.2 观测地点地图
- **需求编号：** SRS-VIS-002
- **需求描述：** 在地图上展示所有观测记录发生的位置（经纬度），数据来源为模块三。
- **交互要求：** 点击地图上的观测点标记，可弹出观测概要卡片（时间、生态系统、观测人员、发现物种数量）。

#### 3.4.3 统计分析图表
- **需求编号：** SRS-VIS-003
- **需求描述：** 系统提供以下统计分析图表：
  1. **物种数量统计：**
     - 各分类单元占比（如各门、各纲的物种数量分布）
     - 保护等级占比（极危、濒危、易危、无危等）
     - 数据来源：模块二
  2. **生态系统统计：**
     - 各生态系统类型的观测次数
     - 各生态系统发现的物种数（去重）
     - 数据来源：模块三
  3. **观测活动统计：**
     - 按时间维度（年/月）的观测次数趋势
     - 按观测人员的活动频次排名
     - 数据来源：模块三

#### 3.4.4 综合数据看板
- **需求编号：** SRS-VIS-004
- **需求描述：** 提供一个首页或独立的数据看板页面，集中展示系统关键指标和上述核心图表：
  - 关键指标：物种总数、观测记录总数、生态系统类型数、本月新增观测数等
  - 布局要求：关键指标卡片置顶，下方分区展示地图和各类图表

#### 3.4.5 数据导出
- **需求编号：** SRS-VIS-005
- **需求描述：** 系统支持将查询结果和统计图表数据导出为常用格式：
  - 表格数据导出为 Excel（.xlsx）
  - 图表/报表导出为 PDF
- **业务规则：** 导出内容应与当前用户权限匹配，用户仅能导出其权限范围内的数据。

## 4. 非功能性需求

### 4.1 性能需求
- **SRS-NF-001（页面响应）：** 常规页面加载时间应小于1秒（在标准网络环境下）。
- **SRS-NF-002（地图与查询）：** 地图渲染和数据查询操作的响应时间应小于3秒。
- **SRS-NF-003（并发支持）：** 系统应能支持至少50个并发用户进行常规查询操作而无明显性能下降。

### 4.2 可靠性需求
- **SRS-NF-004（高可用性）：** 系统在学期内的教学科研高峰期应保持高可用性，计划外宕机时间应最小化。
- **SRS-NF-005（数据备份）：** 系统应支持定期自动数据备份机制，防止数据丢失。

### 4.3 安全性需求
- **SRS-NF-006（密码安全）：** 用户密码必须以加密形式存储（建议使用强哈希算法，如BCrypt）。
- **SRS-NF-007（传输安全）：** 前后端通信建议使用HTTPS协议，防止数据在传输过程中被窃取或篡改。
- **SRS-NF-008（访问控制）：** 严格实施基于角色的访问控制（RBAC），防止越权操作；所有敏感操作需进行后端权限校验。
- **SRS-NF-009（输入校验）：** 对用户输入进行有效性校验和过滤，防止SQL注入和XSS跨站脚本攻击。
- **SRS-NF-010（日志审计）：** 对关键数据操作（删除、批量修改、权限变更）记录审计日志。

### 4.4 易用性需求
- **SRS-NF-011（界面设计）：** 界面设计应简洁直观，符合现代Web应用审美标准，支持响应式布局以适配不同设备。
- **SRS-NF-012（操作反馈）：** 用户在执行增删改操作后，系统应提供明确的成功/失败提示和操作反馈。
- **SRS-NF-013（地图交互）：** 地图操作应流畅，提供缩放、平移、点击查看详情等标准交互。

### 4.5 可扩展性需求
- **SRS-NF-014（架构扩展）：** 系统架构应便于未来新增功能模块，如物种基因数据管理、生态系统关联分析、更多类型的观测数据字段等，避免对现有核心功能产生破坏性变更。

## 5. 风险分析

| 风险类型 | 风险描述 | 缓解措施 |
|---------|---------|---------|
| 技术风险 | 小组成员对SpringBoot、Vue、GIS地图集成等技术栈熟悉程度不一，可能影响开发进度 | 组织技术分享与代码Review；采用渐进式开发，优先完成核心数据模块 |
| 数据风险 | 初始真实数据不足，影响系统测试和演示效果 | 编写脚本生成高质量模拟数据；尝试联系相关教研室获取脱敏数据 |
| 范围蔓延风险 | 开发过程中可能不断提出新需求，导致进度失控 | 严格遵循本文档定义的需求范围；任何变更需经小组和指导教师评估后方可纳入 |

## 6. 约束条件

### 6.1 开发过程约束
- 采用敏捷开发模式，进行2-3次迭代开发。
- 使用Git进行版本控制，规范代码提交（Commit Message）和分支管理（建议采用Git Flow或GitHub Flow）。
- 需定期进行小组会议并向指导教师汇报进度。

### 6.2 运行环境及技术约束
- **后端：** 建议使用SpringBoot框架。
- **前端：** 建议使用Vue.js框架（推荐Vue 3）。
- **数据库：** 推荐使用MySQL或PostgreSQL。
- **地图服务：** 使用开源地图库（如Leaflet），避免依赖商业API。
- **开源优先：** 整体技术栈应优先选择开源产品，降低部署和授权成本。
